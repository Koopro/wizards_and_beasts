# Visual Renaissance — VR-0 audit (2026-11-04)

Evidence-based audit of how Wizards & Beasts looks today, and the smallest sequence of work that would make it look
substantially more polished. No production code or asset was changed for this audit.

Companion files: `visual_renaissance/CREATURE_INVENTORY.md` (all 107 creatures, measured) and the contact sheets in
`visual_renaissance/*.jpg`. Earlier visual documents remain the rules: `VISUAL_STYLE_REPORT.md` (source of truth),
`VISUAL_STYLE_GUIDE.md`, `ART_PIPELINE.md`, `GUI_DESIGN_SYSTEM.md`.

---

## 1. Executive summary

The mod does not need a broad redesign. Creatures, GUI, items and icons already share one pixel language, and most of
what players see daily reads well in a real client. The weak points are few, specific and verifiable:

1. **The build was red because the wand rig and its data disagreed.** `wand.geo.json` (commit `fcfea8bd`, "Wand model
   redone") has no tip and no core variants, while all ten woods named a tip; the Talon handle had five fractional
   cubes and the knotty grain sheet stray paint. **Fixed in VR-1a (2026-11-04), build green** — see the end of this
   document.
2. **Spellcasting has no body language.** A full cast-pose system exists (wind-up, release, recovery, hold, synced),
   but no spell declares `castTiming` and `SpellCastAnimationS2CPayload.broadcast` has no caller. In play the arm does
   what vanilla does. The pose numbers are marked as placeholders.
3. **Spell VFX have never been seen.** Beams, Protego, Patronus, Apparition and broom flight have no capture harness
   and no screenshot anywhere. They are the mod's identity and the least verified part of it.
4. **A few iconic creatures are weak**: the Hippogriff (a horse with a beak; alpha roster), the Thunderbird (a squat
   box), the Centaur's human half.
5. **Settlement buildings share one shell.** Wandmaker, Keeper and Teller have the same front; Wandmaker and Reading
   Room the same bookshelf interior. A façade rework is in progress (uncommitted, see §2).
6. **Audio is entirely borrowed.** 103 sound events, 0 audio files: every event remaps to a vanilla sound.
7. **Patronus**: 4 of the 8 forms (horse, fox, goat, bat) draw as the fallback stag.

Recommended first milestone (VR-1): restore the wand tips and a green build, then wire and author the cast poses,
then a spell-VFX capture harness so Protego, beams and the Patronus can finally be judged (§13).

## 3. Existing visual architecture

| Area | How it works today |
|---|---|
| Creatures | 107 entities: 96 data-driven (`ModCreatures` manifest + `creatures/<id>.json`: body plan, hitbox, `scale`, model/texture/animation, declared clips) and 11 Java. All GeckoLib. Rigs, skins and clips are generated by `tools/<id>_model.py` on `rigkit` (local tools repo). Size via `Attributes.SCALE` (model and hitbox together). |
| Player | Vanilla player model, posed by a **pose layer** (`client/pose/`): a priority-ordered stack of procedural passes (Cast, Flight, Apparition, ItemUse, Procedural) applied at the tail of `PlayerModel.setupAnim` by `PlayerModelMixin`; broom rider and petrify are legacy handlers on the same hook. Cast state arrives over `SpellCastAnimationS2CPayload`; flight state is server-derived (`FlightStateDeriver`). Animagus and heritage forms render GeckoLib rigs over the player (`PlayerFormRig`) or vanilla animal models. |
| Spells / VFX | `client/beam/`: `BeamEntityRenderer` re-traces every frame; `BeamGeometry` (whole-pixel core, stepped shells, sparks), `BeamStyle`/`BeamShape`/`BeamQuality` (LOW/MEDIUM/HIGH), a style editor. 15 mod particle types (`arcane_mote`, `dark_wisp`, `smoke_puff`, `light_glow`, `electric_arc`, Protego deflect/shatter, broom trails, …). Protego: a GeckoLib entity drawn full-bright translucent, colour by shape/tier, alpha by integrity, clips `idle_disc`, `idle_dome`, `deflect`, `fade`, `shatter`, `horribilis_absorb`. Patronus: particle trail + a silver-tinted model. |
| Brooms | One master GeckoLib rig, one variant per slot chosen from data (`BroomRenderer`), shared hover bob (`BroomVisuals`), astride rider pose, camera roll and pull-back by events (`BroomCameraHandler`), speed-scaled wind/particles/FOV each configurable to off (`BroomFlightFx`). |
| World | Jigsaw hamlet: plaza + five role buildings from `tools/gen_hamlet_nbt.py`; location block sets (Hogwarts, Hogsmeade, Diagon, Gringotts, Ministry); Chamber of Secrets dungeon. |
| GUI | Parchment kit (`gui_parchment.py`), per-screen chrome (`gui_chrome.py`), shared components in `client/gui/ui` (`UiSurface`, `UiText`, `Ui`, `UiIcons`), tokens in `WizardsPalette`/`WizardsMetrics`, eight material skins. 44 screen classes. |
| Audio | `ModSounds` + `sounds.json`: 103 named, semantic events (`protego_block`, `apparition_crack_elf`, `broom_wind_fast`, …), each remapped to vanilla sounds. |
| Tooling | Dev-only capture harnesses in `client/debug/`: Entity, Form, Equipment, Item, Block, Location, Artefact, Chamber, Career, Companion, Admin, UI screens, Hamlet playtest. None casts a spell or flies a broom. |

## 10. Compatibility risks

- `PlayerModelMixin` writes poses after vanilla `setupAnim`; other mods posing the player (emote, animation
  libraries, first-person mods) can fight it. The unmerged `spike/pal-eval` evaluated an animation library; no
  decision is recorded.
- Shaders: Protego and Patronus use translucent emissive render types and the beam uses custom render types; shader
  packs often break these. Never tested.
- Full-bright translucent wards and wand-tip lights should be checked against Fabulous graphics.
- Resource packs: all audio is vanilla, so a resource pack that changes vanilla sounds changes the mod's sounds too.

## 11. Performance considerations

- `BeamEntityRenderer` re-traces every frame per active beam (deliberate, to avoid 20 Hz stepping); fine for a few
  beams, unmeasured for a duel crowd.
- Broom FX allocate nothing per tick and cap particles; `BeamQuality` has three levels.
- Creature AI is tiered (`CREATURE_AI_SCHEDULING.md`); rendering cost of large rigs (dragons 55–80 cubes) is
  unmeasured on low-end GPUs.
- No measurement was taken in this audit; the client ran capped at 30 fps.
